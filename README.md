# КТИТС-ИНФО

Информационный киоск техникума: расписание занятий и звонков, преподаватели, новости, афиша и схема этажей. Контент редактируется через веб-панель администратора и хранится в MySQL.

- Киоск: `http://ktits-info/`
- Панель администратора: `http://ktits-info/admin/`
- Точка входа API: `api/index.php`

## Требования

- OpenServer с Apache/Nginx, PHP 8.1 и MySQL 8.0;
- расширения PHP `pdo_mysql` и `json`, а для smoke-теста — `curl`;
- Node.js 18 или новее для сборки фронтенда.

## Установка на OpenServer

1. Разместите проект в `C:\OSPanel\domains\KTITS-INFO` и настройте домен `ktits-info` с корнем в этой папке. Перезапустите OpenServer после изменения настроек домена.
2. Импортируйте `KTITS-INFO.sql` в MySQL через phpMyAdmin. Дамп создаёт базу `ktits_info` и начальные данные.

   **Важно:** дамп удаляет и заново создаёт одноимённые таблицы. Не импортируйте его поверх базы с нужными данными без резервной копии.

3. Запустите установщик из командной строки в корне проекта:

   ```bash
   "/c/OSPanel/modules/php/PHP_8.1/php.exe" install.php
   ```

   Если базы ещё нет, установщик может сам создать её и импортировать дамп. Если таблица `users` уже существует, данные сохраняются, а повторный импорт пропускается.

4. Сохраните выведенные пароли. Они генерируются случайно и показываются только при создании пользователя или замене метки `SET_ON_INSTALL`; при повторном запуске существующие пароли не меняются и повторно не выводятся.

Установщик создаёт три учётные записи:

| Логин | Роль | Доступ |
| --- | --- | --- |
| `admin` | Администратор | Все разделы и управление пользователями |
| `schedule` | Редактор расписания | Расписание занятий и звонков |
| `content` | Редактор контента | Преподаватели, новости, афиша и карта этажей |

После установки войдите в `http://ktits-info/admin/` с выданным паролем соответствующего пользователя.

## Настройки базы данных

Подключение задаётся переменными окружения веб-сервера. Если переменная не задана, используется значение по умолчанию из `api/Core/Config.php`.

| Переменная | Значение по умолчанию |
| --- | --- |
| `KTITS_DB_HOST` | `127.0.0.1` |
| `KTITS_DB_PORT` | `3306` |
| `KTITS_DB_NAME` | `ktits_info` |
| `KTITS_DB_USER` | `root` |
| `KTITS_DB_PASS` | пустая строка |

Задайте переменные в конфигурации виртуального хоста OpenServer, если параметры отличаются. Например, для Apache:

```apache
SetEnv KTITS_DB_HOST "127.0.0.1"
SetEnv KTITS_DB_PORT "3306"
SetEnv KTITS_DB_NAME "ktits_info"
SetEnv KTITS_DB_USER "root"
SetEnv KTITS_DB_PASS ""
```

Установщик использует те же переменные окружения. При запуске из Git Bash их можно передать в команду:

```bash
KTITS_DB_USER=root KTITS_DB_PASS=secret "/c/OSPanel/modules/php/PHP_8.1/php.exe" install.php
```

## Структура проекта

- `api/` — PHP API: контроллеры, ядро, сервисы и служебное хранилище;
- `admin/` — панель администратора на чистом JavaScript;
- `js/app.jsx` — точка входа React;
- `js/core.jsx` — общий код фронтенда;
- `js/screens-*.jsx` — экраны киоска;
- `js/map.js` — императивная отрисовка карты;
- `js/dist/` — результат сборки Vite; файлы здесь не редактируют вручную;
- `css/` — стили киоска;
- `assets/` — логотипы, шрифты и изображения;
- `uploads/` — загруженные через админку файлы; у PHP должно быть право записи;
- `tools/` — вспомогательные скрипты, включая smoke-тест API и портативный Node.js при его наличии.

## Сборка фронтенда

Babel в браузере не используется. Vite компилирует JSX и собирает один файл `js/dist/app.js`.

```bash
npm install
npm run build
```

Если системный Node.js не установлен, в комплекте может быть портативная версия:

```bash
export PATH="/c/OSPanel/domains/KTITS-INFO/tools/node:$PATH"
node --version
npm install
npm run build
```

После изменения `js/app.jsx`, `js/core.jsx` или `js/screens-*.jsx` выполните сборку заново. Файл `js/map.js` подключается в `index.html` отдельно и не входит в Vite-бандл, поэтому его правки не требуют сборки. После обновления файлов обновите страницу с обходом кэша: статика может кэшироваться веб-сервером и браузером.

## Обновление карты через админку

Откройте раздел **«Карта этажей»** и выберите этаж. Используйте только планы и координаты, предоставленные заказчиком.

- В свободной планировке помещение перемещается мышью (drag-and-drop). После отпускания кнопки новые координаты сохраняются автоматически.
- Щёлкните по помещению, чтобы открыть его карточку. В ней можно изменить название, уникальный код, тип, координаты `X`/`Y`, ширину и высоту, затем нажать **«Сохранить помещение»**. Отдельных графических ручек ресайза нет: размер меняется числовыми полями.
- Кнопка **«Добавить помещение»** создаёт блок в центре схемы. Укажите название, код и тип, после чего перетащите блок в нужное место.
- Удаление выполняется из карточки выбранного помещения после подтверждения. Помещение также исчезает с киоска и перестаёт быть доступным для подсветки в событиях афиши.
- Если этаж использует строчную планировку, сначала нажмите **«Перевести этаж в свободную планировку»**. Текущее положение помещений сохранится, но обратный переход через админку не предусмотрен.

Загрузка графической подложки и редактор маршрутной сети в текущей версии админки не реализованы.

## Smoke-тест API

Тест выполняет только чтение данных и попытки входа: публичный `bootstrap`, неверный и верный `login`, чтение карты и расписания, проверки неизвестного действия и неподдерживаемого метода.

```bash
"/c/OSPanel/modules/php/PHP_8.1/php.exe" tools/scripts/smoke_api.php
```

По умолчанию используются `http://ktits-info` и учётные данные локальной среды `admin` / `admin123`. Их можно переопределить:

```bash
KTITS_BASE_URL="http://ktits-info" \
KTITS_ADMIN_LOGIN="admin" \
KTITS_ADMIN_PASSWORD="пароль_из_установщика" \
"/c/OSPanel/modules/php/PHP_8.1/php.exe" tools/scripts/smoke_api.php
```

Для каждой проверки выводится `PASS` или `FAIL`. При любом сбое скрипт завершается с ненулевым кодом. Учтите, что API при успешном входе сам обновляет время последнего входа и журнал авторизации; тест не изменяет контент сайта.
